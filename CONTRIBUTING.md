# Contributing to ADEF

Thank you for helping improve ADEF.

## Principles

- Prefer practical guidance over documentation for its own sake.
- Keep the framework technology-neutral where possible.
- Separate mandatory engineering concerns from optional artifacts.
- Explain both when to use an artifact and when not to use it.
- Preserve compatibility with human-led and AI-assisted engineering workflows.

## Contributions

For substantial changes, explain the problem, proposed change, alternatives, and impact on the framework. Keep examples concise and reusable. Avoid vendor-specific recommendations unless clearly marked as examples.

## Pull requests

A pull request should have a focused purpose, clear rationale, and updated documentation when behavior or framework guidance changes.

# إطار الهندسة الموجّهة بالمعمارية (ADEF)

> إطار هندسي عملي وجاهز لعصر الذكاء الاصطناعي لتصميم وبناء والتحقق من ونشر وتشغيل وتطوير الأنظمة البرمجية.

[English](README.md) | [العربية](README.ar.md)

## لماذا يوجد ADEF؟

أصبحت أدوات الذكاء الاصطناعي قادرة على توليد الكود بسرعة أكبر من قدرة الفرق على حفظ المنطق والقرارات الهندسية التي تقف خلفه. لذلك يتعامل ADEF مع المعرفة الهندسية كأصل أساسي داخل المشروع، بحيث يعمل البشر ووكلاء الذكاء الاصطناعي انطلاقًا من نفس الرؤية والمتطلبات والمعمارية والقرارات والعقود والقيود الأمنية والسياق التشغيلي.

> **الكود يجب أن يكون نتيجة للقرارات الهندسية، وليس نقطة البداية لاتخاذها.**

ADEF ليس قائمة إلزامية لكتابة كل وثيقة ممكنة. استخدم أقل مجموعة من المخرجات التي تمنح مشروعك الوضوح وقابلية التتبع والثقة الهندسية المطلوبة.

## دورة الحياة الهندسية

```text
Business → Product Vision → Requirements → Scope → Architecture
→ Architecture Decisions → Technical Design → Contracts
→ Implementation → Testing & Validation → Deployment → Operations → Evolution
```

## ماذا يقدم ADEF؟

- هيكل موحد لتوثيق المعرفة الهندسية.
- قوالب قابلة لإعادة الاستخدام مثل PRD وADR وTDD وRFC وRunbook.
- إرشادات توضّح متى تستخدم كل وثيقة ومتى لا تحتاجها.
- ملف `AGENTS.md` كنقطة دخول لوكلاء البرمجة بالذكاء الاصطناعي.
- مستويات توثيق قابلة للتوسع من MVP حتى الأنظمة المؤسسية والمنظمة.
- طبقة AI اختيارية للأنظمة التي تحتوي فعلًا على قدرات ذكاء اصطناعي.

## مستويات الاستخدام

| المستوى | مناسب لـ | النطاق المعتاد |
|---|---|---|
| **Essential** | النماذج الأولية والأدوات الداخلية وMVP | الرؤية، النطاق، المعمارية، القرارات المهمة، معايير القبول |
| **Standard** | تطبيقات الإنتاج | المتطلبات، C4، التصميم، العقود، الأمن، الاختبارات، النشر، التشغيل |
| **Enterprise / Regulated** | الحكومي والمالي والصحي والأنظمة الحرجة | تتبع كامل، أمن رسمي، مرونة تشغيلية، حوكمة، أدلة تدقيق |
| **AI Extension** | الأنظمة التي تستخدم نماذج أو LLMs | معمارية AI، استراتيجية النموذج، عقود الـPrompt، السلامة، التقييم، توثيق النموذج |

استخدام أداة AI للمساعدة في كتابة الكود لا يجعل النظام نفسه نظام ذكاء اصطناعي.

## من Prompt إلى Engineering

بدلًا من:

```text
Prompt → Code
```

نستهدف:

```text
Intent → Specification → Architecture → Decisions → Design & Contracts
→ Human + AI Implementation → Verification → Production → Feedback → Evolution
```

الفكرة الأساسية أن الوكيل لا يحتاج إلى تذكر كل شيء، بل يحتاج إلى مصدر حقيقة موثوق يستطيع اكتشافه والرجوع إليه.

## كيف تبدأ؟

1. اختر أصغر مستوى توثيق مناسب للمشروع.
2. ابدأ بالهدف والنطاق قبل المعمارية والتنفيذ.
3. سجّل القرارات المؤثرة في ADRs.
4. استخدم TDD عندما يستحق التغيير تصميمًا تقنيًا صريحًا.
5. اعتبر العقود حدودًا ملزمة للتنفيذ.
6. عرّف طريقة التحقق قبل اعتبار الكود مكتملًا.
7. احتفظ بمعرفة التشغيل والتطور داخل نفس مصدر الحقيقة.
8. حدّث الوثائق عند تغير القرار نفسه.
